# Marketing Core C5 — Ads UI (approval inbox, activity, settings) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give marketing people three pages in Heblo's Marketing section — an approval inbox for ad-change proposals, an activity view (audit log, out-of-band changes, agent runs) and an admin settings page (autonomy, limits, kill switch) — on top of the REST endpoints shipped by core PRs C2 and C3.

**Architecture:** Pure frontend PR (plus regenerated access-matrix artifacts). All server calls go through the generated NSwag client (`getAuthenticatedApiClient()`, absolute base URL) inside three React Query hook files; the hooks map generated DTOs into local view models (`api/hooks/marketingAds/types.ts`) so components never depend on generated class names or on whether a date arrived as a `Date` or a string. The human-readable diff is rendered by Heblo's frontend from the structured `actions` payload, never from the agent's free-text reasoning, which is shown in a separate, visually distinct block as plain text. Approve/reject always send the proposal id **and** the version the user is looking at; a 409 shows a stale-version banner that forces an explicit refresh.

**Tech Stack:** React 18 + TypeScript (CRA / `react-scripts`), TanStack Query v5, react-router-dom v6, Tailwind (graphite dark theme), lucide-react, Jest + Testing Library (`react-scripts test`), Playwright (nightly E2E against staging).

**Spec:** `docs/superpowers/specs/2026-10-07-marketing-agents-platform-design.md` (sections 6, 7.2, 8, 10 bind this plan; section 12 fixes names). Context: `docs/handoff/marketing-agents-platform.md`.

## Global Constraints

- Routes are exactly `/marketing/ads/proposals`, `/marketing/ads/activity`, `/marketing/ads/settings` (spec 8). A proposal detail is addressed as `/marketing/ads/proposals?proposal=<id>` (no extra route).
- Permission strings (generated by `AccessMatrixGen` from the features C3 adds; spec 7.2 lists them under C4): `marketing.ads.read` (Marketing_Ads Read), `marketing.ad_approvals.write` (Marketing_AdApprovals Write — approve/reject in web UI), `marketing.ad_approvals.admin` (Marketing_AdApprovals Admin — autonomy, limits, kill switch, revert). Gate UI only via `usePermissionsContext().hasPermission(...)`, never legacy role strings.
- Approve/reject "must name the **current** version; otherwise 409" (spec 6.2). The UI sends the id + version it rendered, never re-reads the version at click time, and never silently retries.
- "Human-readable diff is **rendered by Heblo from `actions`**, never from `reasoning`" (spec 6.1). Reasoning is rendered as plain text (no HTML, no Markdown) in its own block labelled as the author's/agent's text.
- "Revert: web UI only, `Marketing_AdApprovals` Admin, uses stored before-state per action" (spec 6.2).
- "Changing a mode needs `Marketing_AdApprovals` Admin. The approval-without-edit rate per action type is shown next to the setting" (spec 6.4).
- Kill switch: "Default after deployment: **execution disabled** … Flipping it is audited" (spec 6.6). Every flip in the UI goes through a confirmation dialog.
- "Performance charts are **not** built in Heblo (ADR-007/008): the pages link to the Metabase dashboards built on the `v_ads_*` views" (spec 8).
- UI copy is Czech, hard-coded in components like every other `components/marketing/**` page (no `useTranslation`). Backend `ErrorCodes` translations live in `frontend/src/i18n.ts` and are owned by C3.
- Light + dark mode: every raw Tailwind colour class gets its `dark:` counterpart per `docs/design/dark-mode-conversion-guide.md`. Page shell = `PAGE_CONTAINER_HEIGHT` flex column like `MarketingPerformancePage`.
- API hooks use `getAuthenticatedApiClient()` (absolute `config.apiUrl`). Never a relative `fetch`, never `(apiClient as any)`.
- No backend source changes in C5. The only backend files touched are the access-matrix artifacts regenerated by `AccessMatrixGen`.
- Commits: conventional (`feat:`, `test:`, `docs:`, `chore:`), each message ends with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- FE gate: `CI=false npm run build` + `npm run lint` (never trust `tsc -p` — it false-greens). Unit tests: `react-scripts test` (never `npx jest`).

## Review Focus

1. **Version drift while reading** — the detail refetches in the background and the approve button silently sends a newer version the user never saw. Expected: the detail query does not refetch on focus/interval, the button label names the version (`Schválit verzi 3`), and the click sends exactly the rendered version. Pinned by Task 5 test "approves exactly the rendered id and version" and Task 3 test "detail query does not refetch on window focus".
2. **409 arriving as a typed DTO without an HTTP status** — when C3 declares `[ProducesResponseType(typeof(X), 409)]`, NSwag throws the parsed DTO (`{success:false, errorCode}`) instead of a `SwaggerException`, so a `status === 409` check misses it and the user gets a generic error. Expected: stale banner either way. Pinned by Task 2 tests and Task 5 test "treats a typed conflict DTO without an HTTP status as stale too".
3. **Double submit** — a second click on Schválit while the first request is in flight. Expected: both decision buttons disabled while any decision mutation is pending. Pinned by Task 5 test "disables both decision buttons while an approval is in flight".
4. **Server values the UI does not know** (a new action type, status, actor kind added later — spec says action types are additive). Expected: the raw value is shown instead of crashing or showing blank; the diff falls back to a generic line. Pinned by Task 4 tests "falls back to the raw value" and "renders a generic line for an unknown action type".
5. **Prompt-injection / markup in the agent's reasoning** (`<img onerror>`, "ignore limits", Markdown). Expected: rendered literally inside the reasoning block, never as HTML, never inside the diff. Pinned by Task 5 test "renders reasoning as literal text outside the diff".

| 1 | Diff rendered by Heblo (C3 has a server-side diff renderer for MCP) | The web UI renders the diff in the frontend (`renderActionDiff.ts`) from the structured `actions`; any server-rendered text in the DTO is ignored | Keeps the UI independent of the C3 renderer's DTO shape, which was designed in parallel. | 3 | E2E: "approval inbox happy path" | E2E seeds a proposal, verifies diff + reasoning, then **rejects** it; it never approves | Approving on staging enqueues real execution; if an admin ever enabled the kill switch with a live executor, the nightly run would write to a live ad account. Approve is covered by unit tests. |
| 4 | "history tab" | `Historie` lists proposals in every status (incl. pending), newest first | Avoids depending on a multi-status filter in C3's list endpoint. |
| 5 | Out-of-band changes "filterable by platform/actor" | Filters: platform, origin (default `Mimo Heblo`), actor kind | Actor identity strings are free text per platform; actor kind is the stable, server-filterable dimension. |
| 6 | (not specified) | Reject requires a non-empty reason in the web UI | MCP reject takes a reason (spec 7.5); asking for one in the web keeps the audit log comparable. |

```ts
import { readApiErrorEnvelope } from '../../apiErrorEnvelope';
import { extractErrorMessage, resolveSwaggerErrorMessage } from '../../../utils/errorHandler';

/** Error codes that mean "the proposal you are looking at is no longer the current, pending version". */
export const PROPOSAL_CONFLICT_ERROR_CODES: readonly string[] = ['MarketingAdsConcurrentChange', 'AdProposalVersionConflict', 'AdProposalNotPending'];

/** Error codes that mean "this principal/channel may not approve" (spec 7.4). */
export const APPROVAL_FORBIDDEN_ERROR_CODES: readonly string[] = ['Forbidden', 'AdApprovalChannelDenied'];

const HTTP_CONFLICT = 409;
const HTTP_FORBIDDEN = 403;

const statusOf = (error: unknown): number | undefined => {
  const status = (error as { status?: unknown } | null | undefined)?.status;
  return typeof status === 'number' ? status : undefined;
};

const errorCodeOf = (error: unknown): string => String(readApiErrorEnvelope(error)?.errorCode ?? '');

export const isVersionConflict = (error: unknown): boolean =>
  statusOf(error) === HTTP_CONFLICT || PROPOSAL_CONFLICT_ERROR_CODES.includes(errorCodeOf(error));

export const isForbidden = (error: unknown): boolean =>
  statusOf(error) === HTTP_FORBIDDEN || APPROVAL_FORBIDDEN_ERROR_CODES.includes(errorCodeOf(error));

/** Czech message for any failure: translated ErrorCodes first, then the Error message, then a generic text. */
export const describeAdsError = (error: unknown): string =>
  resolveSwaggerErrorMessage(error) ?? extractErrorMessage(error);
```

```ts
 * the version the user is reading, so the content must not change underneath them. A newer
 * version is picked up only through useRefreshAdProposals (explicit "Obnovit detail").

export const useAdProposalQuery = (id: string | null) =>
  useQuery<AdProposalDetail, Error>({
    queryKey: marketingAdsKeys.proposalDetail(id ?? ''),
    queryFn: async () => {
      const client = getAuthenticatedApiClient();
      const response = await client.marketingAds_GetProposal(toApiId(id ?? ''));
      if (!response.proposal) {
        throw new Error('Návrh nebyl nalezen.');
      }
      return mapProposalDetail(response.proposal);
    },
    enabled: id !== null && id !== '',
    refetchOnWindowFocus: false,
  });

  const queryClient = useQueryClient();
```

```ts
import type { AdActionView } from '../../../../api/hooks/marketingAds/types';
import { ENTITY_LEVEL_LABELS, MATCH_TYPE_LABELS, labelFor } from './adLabels';

// The human-readable diff is rendered here from the structured action — never from the agent's
// reasoning (spec 6.1). Values follow the canonical conventions of spec 12.2
// (Absent/Present for negative keywords, Enabled/Paused for ads).

export interface RenderedActionDiff {
  summary: string;
  before: string;
  after: string;
}

const VALUE_LABELS: Readonly<Record<string, string>> = {
  Absent: 'chybí',
  Present: 'přidáno',
  Enabled: 'aktivní',
  Paused: 'pozastaveno',
};

const MISSING_KEYWORD = '(chybí text)';

const targetName = (action: AdActionView): string => action.targetName ?? `#${action.targetExternalId}`;

const target = (action: AdActionView): string =>
  `${labelFor(ENTITY_LEVEL_LABELS, action.targetLevel)} ${targetName(action)}`;

export const renderActionDiff = (action: AdActionView): RenderedActionDiff => {
  const before = labelFor(VALUE_LABELS, action.oldValue);
  const after = labelFor(VALUE_LABELS, action.newValue);

  switch (action.type) {
    case 'AddNegativeKeyword': {
      const keyword = action.payload.text?.trim() ? action.payload.text : MISSING_KEYWORD;
      const matchType = labelFor(MATCH_TYPE_LABELS, action.payload.matchType);
      return { summary: `Vylučující slovo „${keyword}“ (${matchType}) → ${target(action)}`, before, after };
    }
    case 'PauseAd':
      return { summary: `Pozastavit reklamu ${targetName(action)}`, before, after };
    default:
      return { summary: `${action.type} → ${target(action)}`, before, after };
  }
};
```

```tsx
import React, { useState } from 'react';
import { AlertTriangle, RefreshCw } from 'lucide-react';
import { usePermissionsContext } from '../../../../auth/PermissionsContext';
import {
  useApproveAdProposalMutation,
  useRejectAdProposalMutation,
  useRevertAdProposalMutation,
} from '../../../../api/hooks/useMarketingAdsProposals';
import { describeAdsError, isForbidden, isVersionConflict } from '../../../../api/hooks/marketingAds/errors';
import { LIMITS_OUTCOME, PROPOSAL_STATUS, type AdProposalDetail } from '../../../../api/hooks/marketingAds/types';
import { ADS_PERMISSIONS } from '../shared/permissions';
import ConfirmActionDialog from '../shared/ConfirmActionDialog';

interface ProposalDecisionBarProps {
  proposal: AdProposalDetail;
  onRefresh: () => void;
}

type OpenDialog = 'reject' | 'revert' | null;

const FORBIDDEN_MESSAGE =
  'Tento návrh nemůžete schválit: chybí oprávnění Schvalování kampaní, nebo jste ho už schválili a je potřeba jiný schvalovatel.';
const REVERTIBLE_STATUSES: readonly string[] = [PROPOSAL_STATUS.Executed, PROPOSAL_STATUS.PartiallyExecuted];

const PRIMARY_BUTTON =
  'px-4 py-2 text-sm font-medium text-white bg-indigo-600 rounded-md hover:bg-indigo-700 disabled:opacity-50 disabled:cursor-not-allowed';
const SECONDARY_BUTTON =
  'px-4 py-2 text-sm font-medium text-gray-700 dark:text-graphite-muted bg-white dark:bg-graphite-surface border border-gray-300 dark:border-graphite-border rounded-md hover:bg-gray-50 dark:hover:bg-white/5 disabled:opacity-50 disabled:cursor-not-allowed';

const ProposalDecisionBar: React.FC<ProposalDecisionBarProps> = ({ proposal, onRefresh }) => {
  const { hasPermission } = usePermissionsContext();
  const approve = useApproveAdProposalMutation();
  const reject = useRejectAdProposalMutation();
  const revert = useRevertAdProposalMutation();
  const [openDialog, setOpenDialog] = useState<OpenDialog>(null);
  const [reason, setReason] = useState('');
  const [isStale, setIsStale] = useState(false);
  const [errorMessage, setErrorMessage] = useState<string | null>(null);

  const canApprove = hasPermission(ADS_PERMISSIONS.approve);
  const canRevert = hasPermission(ADS_PERMISSIONS.admin);
  const isPending = proposal.status === PROPOSAL_STATUS.Pending;
  const isDenied = proposal.limits?.outcome === LIMITS_OUTCOME.Denied;
  const isBusy = approve.isPending || reject.isPending || revert.isPending;
  // The version the user is looking at — never re-read at click time (spec 6.2: approve names id + version).
  const decision = { id: proposal.id, version: proposal.currentVersion };

  const handleError = (error: unknown) => {
    if (isVersionConflict(error)) {
      setIsStale(true);
      setErrorMessage(null);
      return;
    }
    setErrorMessage(isForbidden(error) ? FORBIDDEN_MESSAGE : describeAdsError(error));
  };

  const closeDialog = () => {
    setOpenDialog(null);
    setReason('');
  };

  const handleApprove = () => {
    setErrorMessage(null);
    approve.mutate(decision, { onError: handleError });
  };

  const handleConfirmReject = () => {
    setErrorMessage(null);
    reject.mutate(
      { ...decision, reason: reason.trim() },
      {
        onSuccess: closeDialog,
        onError: (error) => {
          closeDialog();
          handleError(error);
        },
      },
    );
  };

  const handleConfirmRevert = () => {
    setErrorMessage(null);
    revert.mutate(
      { id: proposal.id },
      {
        onSuccess: closeDialog,
        onError: (error) => {
          closeDialog();
          handleError(error);
        },
      },
    );
  };

  const handleRefresh = () => {
    setIsStale(false);
    setErrorMessage(null);
    onRefresh();
  };

  return (
    <section aria-label="Rozhodnutí o návrhu" className="space-y-3">
      {isStale && (
        <div role="alert" className="flex flex-wrap items-center gap-3 p-3 rounded-md border border-amber-300 dark:border-amber-700 bg-amber-50 dark:bg-amber-900/30 text-sm text-amber-900 dark:text-amber-200">
          <AlertTriangle className="h-4 w-4 flex-shrink-0" aria-hidden="true" />
          <span className="flex-1">
            Návrh se mezitím změnil — existuje novější verze, nebo už byl vyřízen. Obnovte detail a zkontrolujte změny znovu.
          </span>
          <button type="button" onClick={handleRefresh} className={SECONDARY_BUTTON}>
            <RefreshCw className="inline h-4 w-4 mr-1" aria-hidden="true" />
            Obnovit detail
          </button>
        </div>
      )}

      {errorMessage && (
        <div role="alert" className="p-3 rounded-md border border-red-200 dark:border-red-900/50 bg-red-50 dark:bg-red-900/30 text-sm text-red-700 dark:text-red-300">
          {errorMessage}
        </div>
      )}

      {isPending && canApprove && (
        <div className="flex flex-wrap items-center gap-3">
          <button type="button" onClick={handleApprove} disabled={isBusy || isStale || isDenied} className={PRIMARY_BUTTON}>
            {`Schválit verzi ${proposal.currentVersion}`}
          </button>
          <button type="button" onClick={() => setOpenDialog('reject')} disabled={isBusy || isStale} className={SECONDARY_BUTTON}>
            Zamítnout
          </button>
          {isDenied && (
            <span className="text-sm text-red-700 dark:text-red-300">Limity návrh zamítly — schválit ho nelze.</span>
          )}
        </div>
      )}

      {isPending && !canApprove && (
        <p className="text-sm text-gray-600 dark:text-graphite-muted">
          Ke schválení nebo zamítnutí potřebujete oprávnění Schvalování kampaní.
        </p>
      )}

      {REVERTIBLE_STATUSES.includes(proposal.status) && canRevert && (
        <button type="button" onClick={() => setOpenDialog('revert')} disabled={isBusy} className={SECONDARY_BUTTON}>
          Vrátit zpět
        </button>
      )}

      <ConfirmActionDialog
        isOpen={openDialog === 'reject'}
        title="Zamítnout návrh?"
        message={`Zamítáte verzi ${proposal.currentVersion}. Autor uvidí váš důvod.`}
        confirmLabel="Zamítnout návrh"
        tone="danger"
        isPending={reject.isPending}
        isConfirmDisabled={reason.trim().length === 0}
        onConfirm={handleConfirmReject}
        onCancel={closeDialog}
      >
        <label htmlFor="ads-reject-reason" className="block text-sm font-medium text-gray-700 dark:text-graphite-muted mb-1">
          Důvod zamítnutí
        </label>
        <textarea
          id="ads-reject-reason"
          value={reason}
          onChange={(event) => setReason(event.target.value)}
          rows={3}
          className="w-full rounded-md border border-gray-300 dark:border-graphite-border bg-white dark:bg-graphite-surface-2 text-sm text-gray-900 dark:text-graphite-text dark:placeholder-graphite-faint p-2"
        />
      </ConfirmActionDialog>

      <ConfirmActionDialog
        isOpen={openDialog === 'revert'}
        title="Vrátit provedené změny?"
        message="Heblo obnoví u každé provedené akce původní stav uložený před provedením."
        confirmLabel="Vrátit změny"
        tone="danger"
        isPending={revert.isPending}

        onCancel={closeDialog}

    </section>
```

```tsx
  { id: 'history', label: 'Historie' },
];

const PAGE_SIZE = 25;
const PANEL = 'bg-white dark:bg-graphite-surface shadow dark:shadow-soft-dark rounded-md min-h-0';

const MarketingAdsProposalsPage: React.FC = () => {

  const [searchParams, setSearchParams] = useSearchParams();
  const [page, setPage] = useState(1);
  const tab: ProposalTab = searchParams.get('tab') === 'history' ? 'history' : 'pending';
  const selectedId = searchParams.get('proposal');

  const list = useAdProposalsQuery({
    status: tab === 'pending' ? PROPOSAL_STATUS.Pending : null,
    page,
    pageSize: PAGE_SIZE,
  });

  const updateParams = (changes: Record<string, string | null>) => {
    setSearchParams((previous) => {
      const next = new URLSearchParams(previous);
      Object.entries(changes).forEach(([key, value]) => {
        if (value === null) {
          next.delete(key);
        } else {
          next.set(key, value);
        }
      });
      return next;
    });
  };

  const handleTabChange = (nextTab: ProposalTab) => {
    setPage(1);
    updateParams({ tab: nextTab === 'history' ? 'history' : null });
  };

  return (
    <div className="flex flex-col w-full" style={{ height: PAGE_CONTAINER_HEIGHT }}>
      <div className="flex-shrink-0 mb-3 flex flex-wrap items-start justify-between gap-2">
```

```tsx
import { ACTION_TYPE_LABELS, PLATFORM_LABELS, labelFor } from '../shared/adLabels';

const SAVE_BUTTON =
  'ml-2 px-3 py-1 text-sm font-medium text-white bg-indigo-600 rounded-md hover:bg-indigo-700 disabled:opacity-50 disabled:cursor-not-allowed';
const NON_NEGATIVE_INTEGER = /^\d+$/;

const rowKey = (row: AdLimitSetting): string => `${row.platform ?? '*'}|${row.actionType ?? '*'}|${row.key}`;

const scopeText = (row: AdLimitSetting): string =>
  `${row.platform ? labelFor(PLATFORM_LABELS, row.platform) : 'všechny platformy'} – ${row.actionType ? labelFor(ACTION_TYPE_LABELS, row.actionType) : 'všechny akce'}`;

const parseLimit = (raw: string): number | null => (NON_NEGATIVE_INTEGER.test(raw.trim()) ? Number(raw.trim()) : null);

const LimitsTable: React.FC<{ rows: AdLimitSetting[] }> = ({ rows }) => {
  const mutation = useUpdateAdLimitMutation();
  const [drafts, setDrafts] = useState<Record<string, string>>({});
  const [errorMessage, setErrorMessage] = useState<string | null>(null);

  const clearDraft = (key: string) =>
    setDrafts((previous) => Object.fromEntries(Object.entries(previous).filter(([draftKey]) => draftKey !== key)));

  const handleSave = (row: AdLimitSetting, value: number) => {
    setErrorMessage(null);
    mutation.mutate(
      { platform: row.platform, actionType: row.actionType, key: row.key, value },
      {
        onSuccess: () => clearDraft(rowKey(row)),
        onError: (error) => setErrorMessage(describeAdsError(error)),
      },
    );
  };

  return (
    <section aria-labelledby="limits-title" className="bg-white dark:bg-graphite-surface shadow dark:shadow-soft-dark rounded-md p-4">
      <h2 id="limits-title" className="text-base font-semibold text-gray-900 dark:text-graphite-text">Limity</h2>

      {errorMessage && (

          {errorMessage}

        <table data-testid="limits-table" className="min-w-full divide-y divide-gray-200 dark:divide-graphite-border">
          <thead className="bg-gray-50 dark:bg-graphite-surface-2">
            <tr>

              <th className={HEAD}>Platí pro</th>
              <th className={HEAD}>Hodnota</th>
            </tr>
          </thead>
          <tbody className="divide-y divide-gray-200 dark:divide-graphite-border">
            {rows.map((row) => {
              const key = rowKey(row);
              const draft = drafts[key] ?? String(row.value);
              const parsed = parseLimit(draft);
              const isDirty = parsed !== row.value;
              return (
                <tr key={key}>
                  <td className={`${CELL} font-mono text-gray-900 dark:text-graphite-text`}>{row.key}</td>
                  <td className={CELL}>{scopeText(row)}</td>

                      min={0}

                      onChange={(event) => setDrafts((previous) => ({ ...previous, [key]: event.target.value }))}
                    />

                      type="button"
                      className={SAVE_BUTTON}
                      aria-label={`Uložit limit ${row.key}`}
                      disabled={parsed === null || !isDirty || mutation.isPending}

                    )}
                  </td>
```

```ts
import { Page, expect } from '@playwright/test';
import type { AdsProposalSeedFixture } from '../fixtures/test-data';

/**
 * Seeds marketing-ads proposals for the approval-inbox E2E through C3's REST submit endpoint.
 * `page.request` shares the browser context's cookie jar, so after `navigateToApp(page)` the call
 * runs as the E2E user (Web channel). Seeded proposals are rejected by the tests, never approved,
 * so nothing is ever executed against a live ad account.
 */

export interface SeededAdProposal {
  id: string;
  version: number;
  keyword: string;
  reasoning: string;
}

const DEFAULT_FRONTEND_URL = 'https://heblo.stg.anela.cz';

export const adsPageUrl = (path: string): string =>
  `${process.env.PLAYWRIGHT_FRONTEND_URL || process.env.PLAYWRIGHT_BASE_URL || DEFAULT_FRONTEND_URL}${path}`;

export async function seedAdProposal(page: Page, fixture: AdsProposalSeedFixture): Promise<SeededAdProposal> {
  const keyword = `e2e-heblo-${Date.now()}`;
  const reasoning = `E2E seed ${keyword}: automatický test, nikdy neschvalovat.`;

  const response = await page.request.post('/api/marketing-ads/proposals', {
    data: {
      platform: fixture.platform,
      accountExternalId: fixture.accountExternalId,
      actionType: 'AddNegativeKeyword',
      reasoning,
      actions: [
        {
          type: 'AddNegativeKeyword',
          platform: fixture.platform,
          accountExternalId: fixture.accountExternalId,
          targetLevel: 'Campaign',
          targetExternalId: fixture.campaignExternalId,
          oldValue: 'Absent',
          newValue: 'Present',
          payload: { text: keyword, matchType: 'Exact' },
        },
      ],
    },
  });
  expect(response.ok(), `submit proposal failed (${response.status()}): ${await response.text()}`).toBeTruthy();

  const body = await response.json();
  const id = body.id ?? body.proposalId;
  if (id === undefined || id === null) {
    throw new Error(`submit proposal response carries no id: ${JSON.stringify(body)}`);
  }
  return { id: String(id), version: Number(body.version ?? body.currentVersion ?? 1), keyword, reasoning };
}
```

If C3's submit request/response field names differ (see "Before you start" step 5), adapt only this helper.
