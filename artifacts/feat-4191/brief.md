`CreateMarketingActionHandler` and `UpdateMarketingActionHandler` set product associations and folder links through different code paths, even though the domain entity provides canonical bulk-assignment methods for both.

## Why it matters
- **Inconsistency**: The two write handlers express the same initial-set operation through different domain APIs. Future readers may not realize the approaches are equivalent, or may assume Create and Update have different semantics.
- **Drift risk**: If `ReplaceProductAssociations` gains additional validation or invariant checks, the Create path won't inherit them.
- **Redundant complexity**: LINQ `.Distinct()` + per-item guard in `AssociateWithProduct` is three steps to accomplish what `ReplaceProductAssociations` does in one.

## Suggested fix
Replace the manual loops in `CreateMarketingActionHandler` with the same domain methods used by Update:

```csharp

// folder links

    request.FolderLinks?.Select(l => (l.FolderKey, l.FolderType)),
    now);
```

This gives both handlers an identical entry point into the domain, eliminating the inconsistency.
