# [arch-review] MarketingInvoices: Meta Ads access token passed as URL query parameter instead of Authorization header

## Module
MarketingInvoices

## Finding
`MetaAdsTransactionSource.BuildInitialUrl` appends the OAuth access token as a plain URL query parameter (`?access_token=…`):

```csharp
// backend/src/Adapters/Anela.Heblo.Adapters.MetaAds/MetaAdsTransactionSource.cs:111-113
private string BuildInitialUrl(DateTime from, DateTime to) =>
    $"https://graph.facebook.com/{_settings.ApiVersion}/{_settings.AccountId}/transactions" +
    $"?fields=id,time,amount,currency,payment_type" +
    $"&access_token={_settings.AccessToken}" +   // ← token in URL
    $"&time_range=…";
```

`RedactToken` (line 115–122) only redacts the token in the explicit debug-log call. It does not protect against:
- ASP.NET Core / `HttpClient` `DiagnosticListener` events (which log outbound request URLs)
- Azure Application Insights HTTP dependency tracking (logs full request URLs by default)
- Proxy / load-balancer access logs on outbound requests
- Network traces captured during incident investigation

The Meta Graph API fully supports the `Authorization: Bearer <token>` header as an alternative — this is the OAuth 2.0 standard and keeps the credential out of the URL entirely.

## Why it matters
A token that appears in URLs can be inadvertently captured in logs or telemetry and later exposed in a log-search UI (Application Insights, Log Analytics) without requiring any special access to the Key Vault secret itself. The `RedactToken` guard only protects one explicit log call, not the full transport layer.

## Suggested fix
Add the token as a request header instead of a query parameter:

```csharp
// Replace BuildInitialUrl + FetchPageAsync with:
private string BuildInitialUrl(DateTime from, DateTime to) =>
    $"https://graph.facebook.com/{_settings.ApiVersion}/{_settings.AccountId}/transactions" +
    $"?fields=id,time,amount,currency,payment_type" +
    $"&time_range={{\"since\":\"{from.ToUniversalTime():yyyy-MM-dd}\",\"until\":\"{to.ToUniversalTime():yyyy-MM-dd}\"}}";

private async Task<MetaTransactionsResponse> FetchPageAsync(string url, CancellationToken ct)
{
    _logger.LogDebug("MetaAds: GET {Url}", url);   // no token in URL — safe to log as-is

    return await _pipeline.ExecuteAsync(async innerCt =>
    {
        using var request = new HttpRequestMessage(HttpMethod.Get, url);
        request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", _settings.AccessToken);

        var response = await _httpClient.SendAsync(request, innerCt);
        response.EnsureSuccessStatusCode();

        var json = await response.Content.ReadAsStringAsync(innerCt);
        return JsonSerializer.Deserialize<MetaTransactionsResponse>(json, JsonOptions)
               ?? throw new InvalidOperationException("MetaAds API returned null response body.");
    }, ct);
}
```

This eliminates `RedactToken` entirely (no longer needed) and aligns with the OAuth 2.0 bearer token standard (RFC 6750).
