## Finding
`IGiftPackageManufactureService` (Application/Features/Logistics/UseCases/GiftPackageManufacture/Services/IGiftPackageManufactureService.cs) is a fat interface that combines four operations:

- Read: `GetAvailableGiftPackagesAsync` (line 8)
- Read: `GetGiftPackageDetailAsync` (line 10)
- Write: `CreateManufactureAsync` (line 13)
- Write: `DisassembleGiftPackageAsync` (line 19)

Three of the four handlers that inject this interface only use a single method:

- `GetAvailableGiftPackagesHandler` injects the full service but calls only `GetAvailableGiftPackagesAsync`
- `GetGiftPackageDetailHandler` injects the full service but calls only `GetGiftPackageDetailAsync`
- `CreateGiftPackageManufactureHandler` calls only `CreateManufactureAsync`

Each query handler gains implicit access to `CreateManufactureAsync` and `DisassembleGiftPackageAsync` — write operations that have no business being reachable from a read path.

## Why it matters
ISP (Interface Segregation Principle) violation: a query handler should depend only on query capabilities. The fat interface inflates the test-setup surface for every handler test (all mocks must cover the full interface), and makes it possible to accidentally call a command from a query handler. It also obscures where in the codebase a write operation is actually called, since any handler holding the service could invoke it.

## Suggested fix
Split the interface into two:
- `IGiftPackageQueryService` — the two read methods (GetAvailable, GetDetail)
- `IGiftPackageManufactureService` — the two write methods (Create, Disassemble)

`GiftPackageManufactureService` implements both. The concrete class can depend on `IGiftPackageQueryService` internally so `CreateManufactureAsync` and `DisassembleGiftPackageAsync` can still call `GetGiftPackageDetailAsync` without making that method part of the write interface. Query handlers are updated to inject `IGiftPackageQueryService` only.
