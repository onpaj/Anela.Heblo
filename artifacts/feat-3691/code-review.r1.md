If a `Photo` row is deleted (e.g. via `RemovePhotoAsync`, used by `PhotobankIndexJob`) after an earlier page has been fetched but before a later page is fetched, offset-based pagination can silently skip a row that shifts into an already-consumed offset range. Not blocking, but worth being aware of if this endpoint's usage pattern changes (e.g. becomes automated/frequent) or overlaps with a running sync job.
