# Design: Remove application-layer concern from `DailyInvoiceCount` Domain type

## Component Design

### `DailyInvoiceCount` (Domain) — `backend/src/Anela.Heblo.Domain/Features/Analytics/DailyInvoiceCount.cs`
Responsibility: represent a raw day/count pair as returned by `IAnalyticsRepository.GetInvoiceImportStatisticsAsync`. No longer carries any application-configured state.
- Loses the `IsBelowThreshold` property and its setter.
- Retains `Date` (DateTime) and `Count` (int) only.
- Remains a mutable class (unchanged convention), just smaller.

### `DailyInvoiceCountDto` (Application, new) — `backend/src/Anela.Heblo.Application/Features/Analytics/Contracts/DailyInvoiceCountDto.cs`
Responsibility: Application-layer read-model DTO that carries the threshold-aware view of a day's invoice count for the API response. Sixth sibling in this `Contracts/` folder alongside `TopProductDto`, `MonthlyProductMarginDto`, etc.
- Plain C# class (never a record, per repo convention).
- Properties: `Date` (DateTime), `Count` (int), `IsBelowThreshold` (bool) — public getters/setters.
- Namespace: `Anela.Heblo.Application.Features.Analytics.Contracts`.
- No behavior/methods; pure data holder, consistent with existing DTOs in the folder.

### `GetInvoiceImportStatisticsHandler` — `backend/src/Anela.Heblo.Application/Features/Analytics/UseCases/GetInvoiceImportStatistics/GetInvoiceImportStatisticsHandler.cs`
Responsibility: orchestrate the query and own the threshold-comparison logic (an Application-layer concern, since the threshold comes from `InvoiceImportOptions`).
- Stops mutating `DailyInvoiceCount` objects returned by `_analyticsRepository.GetInvoiceImportStatisticsAsync`.
- Projects (`Select`) each `DailyInvoiceCount` into a `DailyInvoiceCountDto`, computing `IsBelowThreshold = dayCount.Count < minimumThreshold` at projection time — same `<` comparison semantics as today, just relocated.
- Continues to read `MinimumDailyThreshold` from `InvoiceImportOptions` unchanged.

### `GetInvoiceImportStatisticsResponse` — `backend/src/Anela.Heblo.Application/Features/Analytics/UseCases/GetInvoiceImportStatistics/GetInvoiceImportStatisticsResponse.cs`
Responsibility: API response contract for the invoice import statistics endpoint.
- `Data` changes type from `List<DailyInvoiceCount>` to `List<DailyInvoiceCountDto>`.
- `MinimumThreshold` (int) and inherited `BaseResponse` members (`Success`, etc.) unchanged.
- This also fixes an incidental layering issue: the Domain type was previously serialized straight to the wire; now the wire type is a proper Application-layer DTO.

### `InvoiceImportStatisticsSourceAdapter` — `backend/src/Anela.Heblo.Application/Features/Invoices/Infrastructure/InvoiceImportStatisticsSourceAdapter.cs`
Responsibility: implements `IInvoiceImportStatisticsSource` (Consumer-Owned Contract), unaffected by this feature's data flow (not wired into the handler; out of scope to wire it in). Only change: drop the three dead `IsBelowThreshold = false` initializers from its `DailyInvoiceCount` construction sites, since the property no longer exists on the Domain type.

### `IInvoiceImportStatisticsSource` — `backend/src/Anela.Heblo.Domain/Features/Analytics/IInvoiceImportStatisticsSource.cs`
Responsibility: unchanged interface contract. Only its XML doc comment on `GetDailyCountsAsync` is edited to remove the now-inapplicable sentence about `IsBelowThreshold` always being `false`.

### Frontend: `useInvoiceImportStatistics.ts` — `frontend/src/api/hooks/useInvoiceImportStatistics.ts`
Responsibility: data-fetching hook, unchanged behavior. Import and re-export of the generated type is renamed from `DailyInvoiceCount` to `DailyInvoiceCountDto` (verbatim rename, no alias), matching the auto-regenerated `api-client.ts` export name.

### Frontend: `InvoiceImportChart.tsx` — `frontend/src/components/charts/InvoiceImportChart.tsx`
Responsibility: chart rendering, unchanged behavior. `InvoiceImportChartProps.data` type reference renamed from `DailyInvoiceCount` to `DailyInvoiceCountDto`. Field access (`.date`, `.count`, `.isBelowThreshold`) and `.map()` usage unaffected — only the type name changes.

### Frontend: `api-client.ts` (generated) — `frontend/src/api/generated/api-client.ts`
Not hand-edited. Regenerated by the existing NSwag/codegen build step; the response element class is automatically renamed from `DailyInvoiceCount` to `DailyInvoiceCountDto` because NSwag names the generated TS class after the C# response DTO type.

## Data Schemas

### Domain type: `DailyInvoiceCount` (after change)
```csharp
namespace Anela.Heblo.Domain.Features.Analytics;

public class DailyInvoiceCount
{
    public DateTime Date { get; set; }
    public int Count { get; set; }
}
```

### Application DTO: `DailyInvoiceCountDto` (new)
```csharp
namespace Anela.Heblo.Application.Features.Analytics.Contracts;

public class DailyInvoiceCountDto
{
    public DateTime Date { get; set; }
    public int Count { get; set; }
    public bool IsBelowThreshold { get; set; }
}
```

### Application response: `GetInvoiceImportStatisticsResponse` (changed member)
```csharp
public class GetInvoiceImportStatisticsResponse : BaseResponse
{
    public List<DailyInvoiceCountDto> Data { get; set; }
    public int MinimumThreshold { get; set; }
    // Success, etc. inherited from BaseResponse — unchanged
}
```

### Handler projection (replaces mutation loop)
```csharp
var dailyCounts = await _analyticsRepository.GetInvoiceImportStatisticsAsync(
    startDate, endDate, request.DateType, cancellationToken);

return new GetInvoiceImportStatisticsResponse
{
    Data = dailyCounts.Select(c => new DailyInvoiceCountDto
    {
        Date = c.Date,
        Count = c.Count,
        IsBelowThreshold = c.Count < minimumThreshold
    }).ToList(),
    MinimumThreshold = minimumThreshold
};
```

### HTTP response shape (unchanged, byte-for-byte)
`GET` invoice import statistics endpoint continues to return:
```json
{
  "data": [
    { "date": "2026-06-20T00:00:00Z", "count": 15, "isBelowThreshold": false },
    { "date": "2026-06-21T00:00:00Z", "count": 5, "isBelowThreshold": true }
  ],
  "minimumThreshold": 10,
  "success": true
}
```
Only the underlying OpenAPI schema component name for the array item type changes, from `DailyInvoiceCount` to `DailyInvoiceCountDto` — field names (`date`, `count`, `isBelowThreshold`) and values are unchanged.

### Frontend generated type (auto-regenerated)
`api-client.ts` export renamed:
```ts
// before
export class DailyInvoiceCount implements IDailyInvoiceCount { date: Date; count: number; isBelowThreshold: boolean; }

// after
export class DailyInvoiceCountDto implements IDailyInvoiceCountDto { date: Date; count: number; isBelowThreshold: boolean; }
```
`useInvoiceImportStatistics.ts` and `InvoiceImportChart.tsx` reference `DailyInvoiceCountDto` directly (no local alias introduced).

### Data flow
```
IAnalyticsRepository.GetInvoiceImportStatisticsAsync
  → List<DailyInvoiceCount>            (Domain: Date, Count)
  → handler projects with minimumThreshold
  → List<DailyInvoiceCountDto>         (Application: Date, Count, IsBelowThreshold)
  → GetInvoiceImportStatisticsResponse.Data
  → controller → JSON (date/count/isBelowThreshold/minimumThreshold — unchanged)
  → NSwag regenerates api-client.ts (class renamed to DailyInvoiceCountDto)
  → useInvoiceImportStatistics.ts re-exports renamed type
  → InvoiceImportChart.tsx consumes renamed type for props
  → InvoiceImportStatistics.tsx unaffected (field access only, no type-name reference)
```
