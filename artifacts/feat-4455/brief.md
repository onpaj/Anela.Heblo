## Why it matters
`development_guidelines.md` documents the cross-module communication pattern: **the consumer defines the contract**. Module A declares a slim interface in its own `Contracts/` folder exposing only the operations it consumes; module B provides an adapter. Directly injecting a provider-owned interface into the consumer:

1. Breaks the consumer-owns-the-contract rule — Logistics couples to Manufacture's vocabulary and full surface area.
2. Violates Interface Segregation — Logistics binds to a 9-method contract (`SubmitManufactureAsync`, `UpdateBoMIngredientAmountAsync`, `GetManufactureTemplateAsync`, …) when it uses only `GetSetPartsAsync`.
3. Makes the dependency direction wrong: cross-module Application-layer code coupling to another module's Domain type creates a hidden tight-coupling path.

The existing `ILeafletKnowledgeSource` pattern in the codebase shows the correct form; this is the same shape of violation that pattern was introduced to prevent.
