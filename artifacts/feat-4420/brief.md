## Why it matters
`development_guidelines.md` requires that DTOs for API responses live in `contracts/` of the specific module and are never domain types. Exposing a domain class directly as an API contract:
- Couples the over-the-wire format to internal domain semantics (any domain change breaks the client contract)
- Prevents the domain type from evolving independently (e.g. adding internal-only fields would pollute the API)
- Inconsistent with the established pattern already used in the same module (`DailyInvoiceCountDto`)
