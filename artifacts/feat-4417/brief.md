## Why it matters
Network timeouts, Flexi API outages, and deserialization errors all produce HTTP 404 responses to the caller instead of HTTP 500. The frontend receives "Not Found" and treats the invoice as absent, hiding the real problem. This violates the principle that infrastructure errors must be distinguished from domain "not found" conditions — the caller cannot distinguish between "the invoice does not exist in Flexi" and "Flexi was unreachable."

## Suggested fix
Only catch the narrow case of a genuinely missing invoice (e.g., a specific 404 response from the Flexi client) and let all other exceptions propagate to the global exception handler, which returns HTTP 500:

```csharp
public async Task<GetInvoiceDetailsResponse> Handle(GetInvoiceDetailsRequest request, CancellationToken cancellationToken)
{
    _logger.LogInformation("Getting details for invoice {InvoiceId}", request.InvoiceId);

    var invoice = await _invoicesClient.GetInvoiceByIdAsync(request.InvoiceId);
    // GetInvoiceByIdAsync returns null when the invoice is not found (documented contract).
    var mapped = invoice is null ? null : _mapper.Map<Contracts.ReceivedInvoiceDto>(invoice);

    return new GetInvoiceDetailsResponse
    {
        Invoice = mapped,
        Found = invoice != null
    };
}
```

If `GetInvoiceByIdAsync` can throw for a not-found case, introduce a specific exception type (e.g., `InvoiceNotFoundException`) and handle only that.
