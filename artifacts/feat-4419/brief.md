InvoiceClassification

## Finding
`VatClassificationRule` matches by IČO (company registration number), not by VAT/DIČ, but its class name says "Vat":

`backend/src/Anela.Heblo.Domain/Features/InvoiceClassification/Rules/VatClassificationRule.cs`
```csharp
public string Identifier => "ICO";
public string DisplayName => "IČO";
public string Description => "Porovnání IČO firmy";

public bool Evaluate(ReceivedInvoice invoice, string pattern)
{
    return string.Equals(invoice.CompanyVat?.Trim(), pattern?.Trim(), StringComparison.OrdinalIgnoreCase);
}
```

The field it reads, `ReceivedInvoice.CompanyVat`, is also misnamed — the XML doc on `SupplierVatId` states: *"Distinct from CompanyVat, which holds the IČ."* So `CompanyVat` stores the IČO, not a VAT ID.

## Why it matters
A future developer adding a DIČ-based classification rule is likely to reach for `CompanyVat` (sounds like VAT) and accidentally write a rule that matches IČO instead. The discoverability problem is compounded by the class being named `VatClassificationRule`, which implies it is already the DIČ rule, not the IČO rule.

## Suggested fix
1. Rename `VatClassificationRule` → `IcoClassificationRule` (or `CompanyRegistrationNumberClassificationRule`).
2. Rename `ReceivedInvoice.CompanyVat` → `CompanyIco` (or `CompanyRegistrationNumber`) and update the mapping profile and Flexi client accordingly.
3. These are low-risk renames since they are internal to the module; check the mapping profile and FlexiReceivedInvoiceMappingProfile.cs for all touch points.
