Adding a new state transition means modifying the callback dictionary and adding another private method, violating Open/Closed — callers can't extend without touching the handler. The current structure also conflates two concerns: orchestrating the state change flow (Open/Closed), and executing the side effects per transition (inventory staging, code checks).

## Suggested fix

The main handler keeps orchestration only: fetch box → validate transition → dispatch to strategy → save → return response. Each strategy is independently testable and a new transition requires only a new class, not a handler edit.
