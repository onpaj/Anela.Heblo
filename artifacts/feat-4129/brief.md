Users (ADR-005) / FeatureFlags

## Finding
`FeatureFlagsController.Put()` resolves the current user's identity directly in the controller via `User.Identity?.Name` (line 46) and stamps it onto `UpsertFlagOverrideRequest.UpdatedBy` before dispatching to MediatR:

```csharp
// backend/src/Anela.Heblo.API/Controllers/FeatureFlagsController.cs:46-54
var name = User.Identity?.Name;
if (name is null)
    Logger.LogWarning("UpsertFlagOverride: User.Identity.Name resolved to null...");
var updatedBy = name ?? "unknown";
return HandleResponse(await _mediator.Send(new UpsertFlagOverrideRequest
{
    Key = key,
    IsEnabled = body.IsEnabled,
    UpdatedBy = updatedBy,   // ← audit field stamped in controller
}, ct));
```

`UpsertFlagOverrideRequest.UpdatedBy` (`backend/src/Anela.Heblo.Application/Features/FeatureFlags/UseCases/UpsertFlagOverride/UpsertFlagOverrideRequest.cs:8`) carries the stamped value. `UpsertFlagOverrideHandler` does not inject `ICurrentUserService` — it reads `request.UpdatedBy` trusting the controller.

Additionally, `User.Identity?.Name` does not follow the claim priority chain defined in `CurrentUserService` (oid → NameIdentifier → sub), so it may return a different or null value under some Entra ID token configurations where the name claim is absent.

## Why it matters

ADR-005 (*User Identity Resolution*, `docs/architecture/development_guidelines.md`) explicitly forbids:
- **Controllers resolving identity** — "no `GetCurrentUserId()` helper, no `ICurrentUserService` injection, no stamping `UserId`/`ModifiedBy` onto requests"
- **Request DTOs carrying `UserId` / `ModifiedBy`** — "these are server-resolved, never trusted from the client (spoofing hole)"

While `UpdatedBy` is stamped by the controller (not the client), the violation is structural: identity resolution has leaked out of the handler and into the controller, bypassing `ICurrentUserService`'s claim-priority chain and the canonical pattern. The `"unknown"` fallback also diverges from the canonical fallback strategy.

## Suggested fix

1. **Remove `UpdatedBy` from `UpsertFlagOverrideRequest`.**
2. **Inject `ICurrentUserService` into `UpsertFlagOverrideHandler`** and resolve the name inside the handler:
   ```csharp
   var updatedBy = _currentUserService.GetCurrentUser().GetDisplayName();
   await _repo.UpsertAsync(request.Key, request.IsEnabled, updatedBy, ct);
   ```
3. **Remove the controller-side name resolution** (lines 46–49 of `FeatureFlagsController.cs`); the controller then becomes a straight-through dispatcher like the other actions in the same file.

`GetDisplayName()` (`CurrentUserExtensions`) already handles the "System" fallback for unauthenticated callers, and the priority chain in `CurrentUserService` covers all Entra ID token variants correctly.
