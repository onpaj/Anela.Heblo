## PR Summary
Documents the feature-flag override cache changes from #3971 in the module's process doc, as the process-docs rule requires. The "Data owned" section now explains that a missing cache entry is reloaded by exactly one database query however many requests ask at once, that the reload runs on its own 5-second timeout independent of any request, and that a failed reload is not cached.

Two entries were added to "Known quirks": a cancelled request quietly gets the caller-supplied default and is logged at Debug with `cancelledBy=caller` (real reload failures stay at Warning with `cancelledBy=refresh` or `none`), and a reload already in flight when an admin flips a flag can re-cache the old value for up to 30 s.
