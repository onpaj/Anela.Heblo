## Finding
`GiftPackageManufactureService` (`backend/src/Anela.Heblo.Application/Features/Logistics/UseCases/GiftPackageManufacture/Services/GiftPackageManufactureService.cs`) injects `ICurrentUserService` (line 20) and calls `_currentUserService.GetCurrentUser()` directly inside:
- `CreateManufactureAsync()` (line 155): `_currentUserService.GetCurrentUser().Name ?? "System"`
- `DisassembleGiftPackageAsync()` (line 233): `_currentUserService.GetCurrentUser().Name ?? "System"`

The calling handlers (`CreateGiftPackageManufactureHandler`, `DisassembleGiftPackageHandler`) do not resolve the user at all — they simply delegate to the service and return. This means the user identity resolution has silently migrated from the handler layer (where ADR-005 places it) into an Application service.

## Why it matters
ADR-005 (development_guidelines.md, §User Identity Resolution) states: *"Resolution call-site: inside MediatR handlers that inject ICurrentUserService."*  When a service — not the handler — owns user resolution, the pattern breaks in any context where `ICurrentUserService` depends on `IHttpContextAccessor` (e.g., a background job that calls the same service). The handler can't pass the already-resolved user to the service, making the service implicitly coupled to the HTTP request lifecycle. It also hides a web-context dependency behind an Application layer abstraction.

## Suggested fix
Resolve the user in the handlers and pass the result as a plain `string userName` parameter:

```csharp
// In CreateGiftPackageManufactureHandler:
var user = _currentUserService.GetCurrentUser();
var manufacture = await _giftPackageService.CreateManufactureAsync(
    request.GiftPackageCode, request.Quantity, request.AllowStockOverride,
    user.Name ?? "System", cancellationToken);
```

Update `IGiftPackageManufactureService` and the concrete implementation to accept `string userName` instead of resolving it internally. Remove `ICurrentUserService` from `GiftPackageManufactureService`'s constructor.
