## What's not tested
The `Map` method has three code paths, none of which are covered by tests:
1. Null or empty `shipping.Guid` → returns `ShippingMethod.PickUp`
2. GUID found in `ShoptetApiSettings.InvoiceShippingGuidMap` → returns the configured method
3. GUID not found in the map → logs a warning and silently defaults to `ShippingMethod.PickUp`

## Why it matters
Branch 3 (unknown GUID) is the most dangerous: if a new shipping method is added to Shoptet but not configured in `InvoiceShippingGuidMap`, every affected invoice is silently tagged as `PickUp` — the wrong shipping method — with only a log warning. Because the default return value is identical to the valid PickUp case, this error is invisible in the data until a reconciliation is done against Shoptet.

## Suggested approach
Unit-test with a mocked `IOptions<ShoptetApiSettings>`: (a) null shipping → PickUp, (b) empty GUID → PickUp, (c) known GUID from config → correct method, (d) unknown GUID → PickUp + verify warning is logged. Pure unit tests, no infrastructure. ~1 hour of effort.
