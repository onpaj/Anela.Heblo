## Module
BackgroundJobs

## Finding
`RecurringJobSeeder.SeedDefaultConfigurationsAsync` (`backend/src/Anela.Heblo.Application/Features/BackgroundJobs/Services/RecurringJobSeeder.cs`, lines 49–57) always calls `UpdateConfiguration` for every job that already exists in the DB, even when the seeded fields (`DisplayName`, `Description`, `TimeZoneId`) are identical to what is stored. `UpdateConfiguration` always stamps `LastModifiedAt = now` and `LastModifiedBy = "System"` on the entity before persisting it.

Consequence: every application restart silently overwrites the audit fields on all existing job rows. A user-initiated `CronExpression` or `IsEnabled` change from yesterday now shows `Last modified by: System, at: <restart time>` in the UI instead of reflecting the real author.

The seeder's stated intent (comment on line 17) is to sync developer-owned fields while preserving admin-owned fields — but `LastModifiedAt`/`LastModifiedBy` record *admin-owned* changes and must not be updated when only the developer-owned fields are compared.

## Why it matters
`LastModifiedAt` / `LastModifiedBy` are displayed in the recurring jobs UI and represent the CRON or enable/disable audit trail. Overwriting them on every restart destroys that information. This is a correctness violation: the seeder mutates state it is explicitly designed to preserve.

## Suggested fix
Guard the `UpdateConfiguration` call with a change-check on the seeded fields only:

```csharp
// Only update when developer-owned fields actually differ
var changed = existing.DisplayName != config.DisplayName
           || existing.Description != config.Description
           || existing.TimeZoneId != config.TimeZoneId;

if (changed)
{
    existing.UpdateConfiguration(
        config.DisplayName,
        config.Description,
        existing.CronExpression,   // preserve admin override
        config.TimeZoneId,
        "System",
        now);
    await _repository.UpdateAsync(existing, cancellationToken);
}
```

Alternatively, introduce a dedicated `UpdateSeedableFields` method on the domain entity that does not touch `LastModifiedAt`/`LastModifiedBy`.
