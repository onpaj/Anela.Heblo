## Why it matters
Handler-to-handler dispatch via the mediator from within a handler violates Clean Architecture's principle that the mediator is an orchestration tool used by the composition root (controllers), not a call-channel between handlers. The concrete problems:

1. **Hidden coupling**: `ChangeTransportBoxStateHandler` now depends on `GetTransportBoxByIdHandler` being registered and behaving correctly, but this dependency is invisible from the class signature.
2. **Double pipeline overhead**: Every state-change triggers the full MediatR pipeline twice — including any logging, validation, and caching behaviors attached to the read path.
3. **Testing cost**: Unit tests for this handler must either mock the entire mediator or arrange a second handler, instead of simply asserting on the repository.
