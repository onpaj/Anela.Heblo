## Module
PackingMaterials

## Finding
Several MediatR `IRequest<>` / `IResponse` types for specific use cases live in `Contracts/` rather than in their own `UseCases/{name}/` folder alongside their handlers. Per `docs/architecture/filesystem.md`, `Contracts/` holds **shared DTOs across use cases**, while each use case owns its request/response co-located with its handler.

Misplaced files:
- `Application/Features/PackingMaterials/Contracts/GetPackingMaterialsListRequest.cs` — contains both `GetPackingMaterialsListRequest` and `GetPackingMaterialsListResponse`; handler is in `UseCases/GetPackingMaterialsList/`
- `Application/Features/PackingMaterials/Contracts/CreatePackingMaterialRequest.cs` — contains `CreatePackingMaterialRequest` and `CreatePackingMaterialResponse`; handler is in `UseCases/CreatePackingMaterial/`
- `Application/Features/PackingMaterials/Contracts/UpdatePackingMaterialRequest.cs` — MediatR request; handler is in `UseCases/UpdatePackingMaterial/`
- `Application/Features/PackingMaterials/Contracts/UpdatePackingMaterialQuantityRequest.cs` — MediatR request; handler is in `UseCases/UpdatePackingMaterialQuantity/`

## Why it matters
A developer looking at `UseCases/CreatePackingMaterial/` sees only the handler — the request/response contract is in a different folder. This breaks the use-case cohesion that the `UseCases/{name}/` structure is designed to provide, and violates the filesystem spec for complex features (4+ use cases).

## Suggested fix
Move each misplaced request/response file into its owning `UseCases/{name}/` folder:
- `GetPackingMaterialsListRequest.cs` and `GetPackingMaterialsListResponse.cs` → `UseCases/GetPackingMaterialsList/`
- `CreatePackingMaterialRequest.cs` and `CreatePackingMaterialResponse.cs` → `UseCases/CreatePackingMaterial/`
- `UpdatePackingMaterialRequest.cs` and `UpdatePackingMaterialResponse.cs` → `UseCases/UpdatePackingMaterial/`
- `UpdatePackingMaterialQuantityRequest.cs` and `UpdatePackingMaterialQuantityResponse.cs` → `UseCases/UpdatePackingMaterialQuantity/`

Keep `Contracts/` for genuinely shared types: `PackingMaterialDto`, `IInvoiceConsumptionSource`, `ConsumptionDetailDto`, etc.
