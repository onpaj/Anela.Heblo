## Why it matters
- Lazy enumerables stored in response objects violate the principle of least surprise: callers expect the data to be ready, not re-queried on each access.
- Any future code that iterates `Tiles` twice (test assertions, middleware, decorators) will re-execute the tile registry lookup and re-allocate objects silently.
- The inconsistency within the Dashboard module (one handler materializes, the other doesn't) makes it harder to spot for reviewers.
