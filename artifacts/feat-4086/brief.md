## Finding
\`UploadDocumentRequest.FileStream\` (declared in \`backend/src/Anela.Heblo.Application/Features/KnowledgeBase/UseCases/UploadDocument/UploadDocumentRequest.cs:8\`) is a \`System.IO.Stream\` opened directly from \`IFormFile.OpenReadStream()\` in the controller (\`KnowledgeBaseController.cs:138\`). The Application-layer handler then reads this stream via \`CopyToAsync\` (\`UploadDocumentHandler.cs:27-29\`):

```csharp

```

This means:
- The Application layer performs HTTP-stream I/O, an infrastructure-layer concern.
- \`UploadDocumentRequest\` is non-serializable. Any pipeline behavior that inspects, logs, or caches the request body will receive an already-read (empty) or otherwise broken stream.
- If a pipeline behavior reads the stream before the handler does, the handler receives empty bytes with no error.
- The DTO cannot safely cross a process boundary (future microservices).

## Why it matters
Clean Architecture places I/O at the boundary (controller / infrastructure). The controller receives the \`IFormFile\`, which is already an ASP.NET abstraction; converting it to \`byte[]\` before constructing the MediatR request keeps the Application layer pure and the DTO serializable. The current pattern also makes \`UploadDocumentRequest\` look like any other request while hiding that it carries a live stream — a silent footgun for any future pipeline behavior author.
