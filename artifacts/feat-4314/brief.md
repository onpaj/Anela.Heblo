## Finding
`frontend/src/components/dashboard/tiles/PackingStatsTile.tsx` (lines 44–49) has its own custom `drillDown` shape (`{enabled, tooltip}`) and hardcodes `navigate('/baleni')` instead of using either of the two established drill-down patterns:

1. **`resolveDrillDown()` pattern** (used by `DataQualityTile`, `FailedJobsTile`): reads `drillDown.routeKey` from a typed `DashboardTileDrillDown` and resolves to a URL via the `DASHBOARD_DRILLDOWN_ROUTES` registry.
2. **`createFilteredUrl(targetUrl, filters)` pattern** (used by `CountTile`): passes `targetUrl` from `tileRegistry.tsx` and uses `data.drillDown.filters` from the backend.

The backend `Anela.Heblo.Application/Features/Packaging/DashboardTiles/PackingStatsTile.cs` (lines 87–92) already emits `drillDown: {filters: {}, enabled: true, tooltip: "..."}` — the `CountTile`-compatible shape — but the frontend tile ignores `filters` entirely and calls `navigate('/baleni')` unconditionally.

## Why it matters
- Violates the project guideline: "Frontend owns routing — URL construction happens in frontend based on its routing structure." The hardcoded path bypasses both the route-key registry and the `tileRegistry.tsx` source-of-truth for target URLs.
- Adding or renaming frontend routes requires hunting for hardcoded strings scattered across tile components instead of updating one registry entry.
- Inconsistent with every other interactive tile, which either use `resolveDrillDown()` or the `CountTile`+`targetUrl` pattern. A developer reading `DataQualityTile` would not know to look for an ad-hoc path in `PackingStatsTile`.

## Suggested fix
Adopt the `CountTile` pattern (it already handles the `filters`-shape drillDown):
1. Add `packingstats` to `tileRegistry.tsx` with `targetUrl="/baleni"` (the same route it hardcodes today).
2. Replace the ad-hoc `onClick` in `PackingStatsTile.tsx` with a `TileDataWithDrillDown`-typed data prop and use `isTileClickable` + `createFilteredUrl(targetUrl, data.drillDown.filters)` — the same four lines `CountTile` uses.
3. Drop the custom `drillDown?: {enabled, tooltip}` interface from `PackingStatsTileProps`; the `TileDataWithDrillDown` type covers it.
