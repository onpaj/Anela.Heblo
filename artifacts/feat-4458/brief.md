## Finding
`CalculateBatchPlanHandler` mutates the incoming MediatR request object directly instead of using local variables:

```csharp
// backend/src/Anela.Heblo.Application/Features/Manufacture/UseCases/CalculateBatchPlan/CalculateBatchPlanHandler.cs:41-46
request.ManufactureType = manufactureTemplate.ManufactureType;
if (request.ManufactureType == ManufactureType.MultiPhase)
{
    request.ProductCode = manufactureTemplate.Ingredients
        .FirstOrDefault(w => w.ProductType == ProductType.SemiProduct)?.ProductCode ?? request.ProductCode;
}
```

Both `request.ProductCode` and `request.ManufactureType` are overwritten on lines 41 and 45. The enriched request is then forwarded to `_batchPlanningService.CalculateBatchPlan(request, ...)` at line 51.

## Why it matters
MediatR request objects are shared across the pipeline: pre- and post-processing behaviors, logging, and activity tracking read the same object before and after the handler body runs. Mutating it creates an inconsistent view — behaviors that ran before the mutation see the original `ProductCode`, while the downstream service sees the enriched semiproduct code. This is a hidden side-effect that will silently break any future behavior that audits or logs the original request values. It also violates the principle that handler inputs are read-only data contracts.

## Suggested fix
Extract the server-enriched values into local variables and pass them to the service without touching the request object:

```csharp
var manufactureType = request.ManufactureType;
var productCode = request.ProductCode;

if (product?.Type == ProductType.Product)
{
    var manufactureTemplate = await _manufactureClient.GetManufactureTemplateAsync(productCode, cancellationToken);
    manufactureType = manufactureTemplate.ManufactureType;
    if (manufactureType == ManufactureType.MultiPhase)
    {
        productCode = manufactureTemplate.Ingredients
            .FirstOrDefault(w => w.ProductType == ProductType.SemiProduct)?.ProductCode ?? productCode;
    }
}

// Pass local vars to the service instead of the mutated request
```
