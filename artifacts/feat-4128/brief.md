## Finding
`IManufactureCatalogSource` is Manufacture's own cross-module contract (correctly placed in `backend/src/Anela.Heblo.Application/Features/Manufacture/Contracts/IManufactureCatalogSource.cs`), but its three methods return `CatalogAggregate` — a type owned by the Catalog module's domain layer (`Anela.Heblo.Domain.Features.Catalog`):

```csharp
// IManufactureCatalogSource.cs, lines 13-20
using Anela.Heblo.Domain.Features.Catalog;           // ← Catalog domain import

public interface IManufactureCatalogSource
{
    Task<CatalogAggregate?> GetByIdAsync(string id, ...);
    Task<IReadOnlyDictionary<string, CatalogAggregate>> GetByIdsAsync(...);
    Task<IEnumerable<CatalogAggregate>> GetAllAsync(...);
}
```

The code acknowledges this in a comment: _"Returns CatalogAggregate as a deliberate pragmatic leak… Follow-up: introduce Manufacture-owned ProductCatalogSnapshot DTO."_ It is allowlisted in `ModuleBoundariesTests` under "Manufacture → Catalog", but no GitHub issue tracks the follow-up work.

Every handler that injects `IManufactureCatalogSource` (e.g. `CreateManufactureOrderHandler`, `CalculatedBatchSizeHandler`, `GetManufacturingStockAnalysisHandler`) also carries `using Anela.Heblo.Domain.Features.Catalog` to work with the returned type, widening the implicit cross-module coupling.

## Why it matters
The cross-module contract pattern documented in `development_guidelines.md` requires the **consumer module** to own both the interface **and** the return-type DTO. When the interface returns a provider-owned domain type:

- Manufacture is forced to depend on the full `CatalogAggregate` shape, including fields it doesn't need — tight coupling instead of the minimal contract the pattern prescribes.
- Any change to `CatalogAggregate` (new required properties, renamed fields, breaking constructor changes) ripples into Manufacture's handlers even when the change is irrelevant to manufacturing.
- The allowlist in `ModuleBoundariesTests` is intentional now, but suppresses the architectural guardrail indefinitely without a tracked ticket.

## Suggested fix
1. Introduce a `ProductCatalogSnapshot` DTO in `backend/src/Anela.Heblo.Application/Features/Manufacture/Contracts/` containing only the fields Manufacture actually reads (product code, name, `Properties.ExpirationMonths`, recipe ingredients, etc.).
2. Update `IManufactureCatalogSource` to return `ProductCatalogSnapshot?` / `IReadOnlyDictionary<string, ProductCatalogSnapshot>` / `IEnumerable<ProductCatalogSnapshot>`.
3. Update `ManufactureCatalogSourceAdapter` in `backend/src/Anela.Heblo.Application/Features/Manufacture/Infrastructure/ManufactureCatalogSourceAdapter.cs` to map from `CatalogAggregate` to `ProductCatalogSnapshot`.
4. Remove the `using Anela.Heblo.Domain.Features.Catalog` imports from Manufacture handlers and the "Manufacture → Catalog" allowlist entry in `ModuleBoundariesTests`.
