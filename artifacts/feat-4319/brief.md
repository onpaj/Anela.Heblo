## Why it matters
Inconsistent cache invalidation leads to stale UI state. The detail query exists precisely for components that need a fresh single-job view — the mutation that changes a job's CRON should invalidate it, just like the status mutation does.

## Suggested fix
Add a detail-query invalidation, matching the status mutation pattern:

```typescript
onSuccess: (_data, variables) => {
  queryClient.invalidateQueries({ queryKey: recurringJobsKeys.list() });
  queryClient.invalidateQueries({ queryKey: recurringJobsKeys.detail(variables.jobName) });
},
```

This requires the mutation's `mutationFn` argument type to expose `jobName` (it already does — the function receives `{ jobName, cronExpression }`).
