## Finding
Both domain entities default `LastModified` to `DateTime.UtcNow` at property-initializer time:

- `backend/src/Anela.Heblo.Domain/Features/Dashboard/UserDashboardTile.cs` line 11:
  `public DateTime LastModified { get; set; } = DateTime.UtcNow;`
- `backend/src/Anela.Heblo.Domain/Features/Dashboard/UserDashboardSettings.cs` line 8:
  `public DateTime LastModified { get; set; } = DateTime.UtcNow;`

`DateTime.UtcNow` is evaluated when the object is constructed, not when it is actually written to the database. In practice, every handler that creates or updates these entities overrides `LastModified` using `TimeProvider.GetUtcNow()` (e.g. `SaveUserSettingsHandler` line 57, `GetUserSettingsHandler` line 40, `UserDashboardSettingsMutator` line 49). But the default is still live:

1. **Silent incorrect timestamp if a handler omits the assignment.** There is no compile-time enforcement that `LastModified` was set before `UpdateAsync`/`AddAsync`. A new handler written without knowing the convention would silently record the construction time, not the write time.
2. **`TimeProvider.Fake` tests see real wall-clock time from the default.** Unit tests that inject `FakeTimeProvider` to control time would still get `DateTime.UtcNow` from the property initializer if the object under test is constructed in the test body and `LastModified` is checked without an explicit override.

## Why it matters
The project uses `TimeProvider` throughout the Dashboard module specifically to make time-dependent code testable and deterministic. A domain entity that captures real `DateTime.UtcNow` at construction time is a local exception to that discipline and a footgun for any handler that forgets the convention.

## Suggested fix
Remove the non-zero defaults; let `LastModified` default to `DateTime.MinValue` (the struct default):

```csharp
// UserDashboardTile.cs
public DateTime LastModified { get; set; }

// UserDashboardSettings.cs
public DateTime LastModified { get; set; }
```

This makes it impossible for an incorrect value to slip through silently — if a handler forgets to set `LastModified`, the stored value will be `0001-01-01`, which is obviously wrong and immediately caught in review or tests.
