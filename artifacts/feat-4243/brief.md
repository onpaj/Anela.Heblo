Configuration

## Finding
`ApplicationConfiguration.CreateWithDefaults` (Domain layer, `backend/src/Anela.Heblo.Domain/Features/Configuration/ApplicationConfiguration.cs`, lines 24–27) hardcodes the fallback strings `"1.0.0"` and `"Production"` directly:

```csharp
return new ApplicationConfiguration(
    version ?? "1.0.0",
    environment ?? "Production",
    useMockAuth
);
```

`ConfigurationConstants` lives in the **same namespace** and defines exactly these values:

```csharp
// backend/src/Anela.Heblo.Domain/Features/Configuration/ConfigurationConstants.cs, lines 8–9
public const string DEFAULT_VERSION = "1.0.0";
public const string DEFAULT_ENVIRONMENT = "Production";
```

The constants class exists to be the single source of truth for these defaults, but the factory method ignores them.

## Why it matters
Duplicate literals mean any change to the defaults requires two edits in two files. The two values are currently identical — but since `CreateWithDefaults` does not reference the constants, a future change to `ConfigurationConstants` will silently leave the factory method stale. This is a DRY violation inside the Domain layer itself.

## Suggested fix
Replace the hardcoded string literals in `CreateWithDefaults` with the constants:

```csharp
return new ApplicationConfiguration(
    version ?? ConfigurationConstants.DEFAULT_VERSION,
    environment ?? ConfigurationConstants.DEFAULT_ENVIRONMENT,
    useMockAuth
);
```

No other changes needed — this is a one-line-per-fallback swap.
