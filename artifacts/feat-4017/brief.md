## What happened

Commit `72784c2` ("chore: update orchestrator and oneshot skill templates
(remove -f from git add)", 2026-08-30) landed on `main` and removed the
`-f` flag from `git add -A artifacts/feat-{n}` in
`.claude/agents/orchestrator.md`, `.claude/agents/plan-orchestrator.md`,
and `.claude/skills/oneshot/SKILL.md`.

This is a regression of the fix already made in #3980 / PR #3991: since
`artifacts/` is `.gitignore`d, `git add -A` without `-f` silently stages
nothing, so a planning/implementing run's `spec.r1.md`, `arch-review.r1.md`,
`design.r1.md`, `task-plan.r1.md`, etc. never actually land in the PR —
exactly the failure mode the orchestrator's own "hard-verify with
`git ls-files --error-unmatch`" step exists to catch.

The commit message claims "Applied by session-start hook", but the actual
`scripts/cloud-session-setup.sh` SessionStart hook does not touch these
files — that attribution appears to be false. The most likely mechanism
(per prior occurrences, see `memory/context/state.md` entries for
#3961/#3969/#3975/#3980/#3987/#3989/#3990/#4003 in the AgentHarness repo)
is a cloud session's `agentharness init` bundled template reverting the
local working-tree copy of these files at session start, and a later
session committing that reverted diff instead of discarding it with
`git checkout --`.

## Impact

Every future `/plan-next-task` or `/implement-next-task` run that follows
`orchestrator.md`/`plan-orchestrator.md`/`oneshot/SKILL.md` literally will
silently fail to commit its own planning/implementation artifacts, unless
the running session happens to notice and route around it (as this one
did, by adding `-f` directly rather than following the current broken
instruction).
