## Finding
`Application/Shared/Users/UserDisplayNameResolver.cs` (lines 18–20) injects `IAuthorizationRepository` (defined in `Domain/Features/Authorization/`) and receives `AppUser` entities from `GetAllUsersAsync()` (Authorization module domain objects). The test file `UserDisplayNameResolverTests.cs` further confirms the coupling by importing `Anela.Heblo.Domain.Features.Authorization.Entities`.

The documented cross-module pattern (`development_guidelines.md`, "Cross-Module Communication" section, and the `ILeafletKnowledgeSource` example) requires the **consumer to own the contract interface** and the **provider to implement an adapter**. Currently, the Shared/Users layer is a consumer that directly depends on Authorization's internal repository contract and its domain entities — the two roles are inverted.

## Why it matters
- Violates module independence: any change to `IAuthorizationRepository` (adding/removing methods, renaming return types) or `AppUser` immediately breaks the cross-cutting shared layer.
- The `Shared/Users` area is used by four modules (KnowledgeBase, Article, Leaflet, Smartsupp); the hidden Authorization dependency propagates through all four.
- Contradicts the enforced pattern (`ModuleBoundariesTests` guards the KnowledgeBase↔Leaflet boundary using the same rule; no test guards Users↔Authorization).
