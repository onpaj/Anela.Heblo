## Finding
`CompanyNameClassificationRule` and `DescriptionClassificationRule` call `Regex.IsMatch` with user-supplied patterns and no `MatchTimeout`. The patterns are entered by application users, stored in the database, and evaluated against every unclassified invoice during the hourly classification job.

The existing try/catch only handles `ArgumentException` (invalid regex syntax) — it does **not** cover catastrophic backtracking, which blocks the thread and never throws.

## Why it matters
A pathological pattern (e.g., `(a+)+$`, or an accidentally ambiguous expression) will cause the thread to spin at 100% CPU until the process is restarted. Because the job runs hourly and applies every active rule to every invoice, a single bad rule hangs the classification job indefinitely, causing thread pool exhaustion and potential service downtime. .NET's default regex engine does not guard against this without an explicit timeout.

## Suggested fix
Pass `TimeSpan` timeout to both calls and catch `RegexMatchTimeoutException`:

```csharp
private static readonly TimeSpan RegexTimeout = TimeSpan.FromMilliseconds(200);

public bool Evaluate(ReceivedInvoice invoice, string pattern)
{
    if (string.IsNullOrWhiteSpace(invoice.CompanyName) || string.IsNullOrWhiteSpace(pattern))
        return false;

    try
    {
        return Regex.IsMatch(invoice.CompanyName, pattern, RegexOptions.IgnoreCase, RegexTimeout);
    }
    catch (RegexMatchTimeoutException)
    {
        return false;  // treat timeout as non-match; log if needed
    }
    catch (ArgumentException)
    {
        return invoice.CompanyName.Contains(pattern, StringComparison.OrdinalIgnoreCase);
    }
}
```

Apply the same pattern to `DescriptionClassificationRule` and `ItemDescriptionClassificationRule`.
