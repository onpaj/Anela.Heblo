# `.agents/planner.md` declares a `context_files` glob that resolves to nothing in cloud sessions

Seen 2026-09-13 on a `/plan-next-task` scheduled run, issue #4155
(`feature/4155-Arch-Review-Orgchart-Orgchartpage-Outer-Wrapper-Mi`).

`.agents/planner.md`'s frontmatter (installed by `agentharness init`) declares:

```yaml
context_files:
  - ~/.claude/plugins/cache/*/superpowers/*/skills/writing-plans/SKILL.md
```

In this cloud/remote session, `~/.claude/plugins/` only has `marketplaces/` and
`synced/` subdirectories — there is no `plugins/cache/` directory at all, so the
glob matches zero files. The `plan-orchestrator` agent's own instructions are
explicit and strict about this: *"If a declared path or glob matches no file,
STOP and report it as a failure instead of running the agent."* This is by
design (an agent silently running without the skill instructions it was
written around is worse than stopping), so a subagent hitting this correctly
refuses to improvise a substitute — it will not fall back to the in-repo
`.claude/skills/writing-plans/SKILL.md` that *does* exist, even though that
file's content is the actual superpowers `writing-plans` skill, because
nothing authorized that substitution.

**Effect: this blocks the `planning` phase (and therefore the whole
`/plan-next-task` pipeline) for every issue in this kind of session**, not
just the one being planned — it is an environment/scaffolding defect, not
anything specific to the claimed issue. Don't burn cycles trying more issues
expecting a different outcome; they'll all hit the same wall at the `planner`
phase.

**What was NOT done, deliberately:** did not patch `.agents/planner.md`'s
`context_files` path to point at the in-repo `.claude/skills/writing-plans/SKILL.md`
instead. That's plausibly the right durable fix, but it's an infrastructure/
scaffolding decision (this file is regenerated by `agentharness init` per the
`gh-cli-unavailable-in-cloud-sessions.md` note's "Root cause of the
repeat-revert loop" section — any local patch needs to go upstream to
`onpaj/harness`'s `agentharness/data/claude-agents/planner.md` the same way
those other scaffolding fixes did, or it'll just get reverted next session
start) and outside what an unattended `/plan-next-task` cycle should decide
unilaterally. The correct move when this recurs is still to stop and report
it plainly — same as any other genuinely-unresolvable blocker this skill's
instructions call out.

**State left behind:** issue #4155's branch already has `analyzing`,
`architecting`, and `designing` artifacts committed and pushed (state.json
`planning: pending`) — a future run, once this is fixed upstream (or if run
in a session where the superpowers plugin cache actually exists), can resume
straight into the `planning` phase without redoing earlier work. The
worktree was removed; the `agent-planning` label was left as-is.

**If you hit this again:** check whether `~/.claude/plugins/cache/` exists
before assuming it's a one-off. If it's still missing, don't attempt the
`planning` phase at all for any issue this cycle — report the blocker
instead of repeatedly re-discovering it per-issue.
